# Отчет об исправлении проблем с деплоем и сборкой

## Проблема

В процессе сборки и деплоя возникли следующие проблемы:

1. **Ошибка архивирования**: `tar: dist: Cannot stat: No such file or directory`
2. **Смешанная структура билдов**: разные приложения использовали разные стили сборки
3. **Дублирование ключей в package.json**: предупреждение о дублировании `test:api`

## Анализ проблемы

### Структура билдов после сборки:
- **Client**: `dist/client/` (NX стиль) ✅
- **MDT Client**: `apps/mdtclient/dist/` (классический стиль) ❌
- **Server**: `dist/apps/server/` (NX стиль) ✅

### Проблема в GitHub Actions:
```yaml
# Старый код - искал только в dist/
tar -czf deployment.tar.gz \
  dist/ \
  package.json \
  package-lock.json \
  # ...
```

Этот подход не учитывал, что MDT Client собрался в классическом стиле (`apps/mdtclient/dist/`).

## Решение

### 1. Обновление GitHub Actions workflow

**Файл**: `.github/workflows/deploy.yml`

**Изменения**:
```yaml
# Новый код - использует умный скрипт
- name: Create deployment package
  run: |
    # Используем умный скрипт для правильного архивирования
    npm run build:archive:correct
    
    # Проверяем, что архив создан
    if [ ! -f deployment.tar.gz ]; then
      echo "❌ Архив deployment.tar.gz не был создан"
      echo "📋 Содержимое текущей директории:"
      ls -la
      echo "📋 Проверяем наличие билд-артефактов:"
      ls -la dist/ 2>/dev/null || echo "dist/ не найден"
      ls -la apps/*/dist/ 2>/dev/null || echo "apps/*/dist/ не найдены"
      exit 1
    fi
    
    echo "✅ Архив deployment.tar.gz создан успешно"
    ls -lh deployment.tar.gz
```

### 2. Улучшение скрипта архивирования

**Файл**: `scripts/build-and-archive-correct.js`

**Изменения**:
- Добавлены все необходимые файлы для деплоя
- Улучшена обработка ошибок
- Добавлена проверка существования архива

```javascript
// Полный набор файлов для деплоя
const deploymentPaths = [
  // Актуальные билд-артефакты
  ...actualBuildPaths.map(bp => bp.path),
  // Конфигурационные файлы
  'package.json',
  'package-lock.json',
  // Дополнительные файлы для деплоя
  'scripts/',
  'supabase/',
  'migrations/',
  'docs/',
  'README.md',
  'node_modules/'
];
```

### 3. Исправление дублирования в package.json

**Файл**: `apps/server/package.json`

**Изменения**:
- Переименован дублирующий ключ `"test:api"` в `"test:api:connection"`
- Устранено предупреждение esbuild

```json
{
  "scripts": {
    "test:api": "jest tests/api/",
    // ... другие скрипты ...
    "test:api:connection": "node test-api-connection.js"
  }
}
```

## Преимущества решения

### 1. Автоматическое определение билдов
- Скрипт автоматически находит актуальные билд-артефакты
- Работает с любым стилем сборки (NX или классический)
- Исключает дублирование и старые файлы

### 2. Надежность
- Проверка существования архива после создания
- Подробная диагностика при ошибках
- Включение всех необходимых файлов для деплоя

### 3. Гибкость
- Поддержка смешанных структур билдов
- Легкая адаптация к изменениям конфигурации
- Совместимость с разными стилями сборки

## Рекомендации

### Краткосрочные:
1. Использовать `npm run build:archive:correct` для всех деплоев
2. Мониторить логи сборки на предмет предупреждений
3. Проверять размер и содержимое создаваемых архивов

### Долгосрочные:
1. **Унифицировать стили сборки**:
   ```javascript
   // Для всех приложений использовать один стиль
   build: {
     outDir: "dist" // Классический стиль
     // ИЛИ
     outDir: "../dist/apps/[app-name]" // NX стиль
   }
   ```

2. **Добавить автоматическую очистку**:
   ```json
   {
     "scripts": {
       "clean": "rm -rf dist/ apps/*/dist/",
       "build:clean": "npm run clean && npm run build"
     }
   }
   ```

3. **Стандартизировать структуру проекта**:
   ```
   dist/
   ├── apps/
   │   ├── client/
   │   ├── mdtclient/
   │   └── server/
   └── shared/
   ```
