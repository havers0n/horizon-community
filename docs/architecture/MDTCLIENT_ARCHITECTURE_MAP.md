# Архитектурная карта @mdtclient/

## Обзор архитектуры

`@mdtclient/` представляет собой современное React-приложение, построенное по принципам **Feature-Sliced Design (FSD)** и **Atomic Design**. Архитектура обеспечивает масштабируемость, переиспользование компонентов и четкое разделение ответственности.

## Структура слоев FSD

### 1. **App Layer** (`src/app/`)
**Назначение**: Инициализация приложения, роутинг, провайдеры

```
src/app/
├── AppRouter.tsx          # Главный роутер приложения
├── components/            # Компоненты уровня приложения
├── layouts/              # Макеты страниц
├── styles/               # Глобальные стили
├── config/               # Конфигурация приложения
├── providers/            # Провайдеры контекстов
└── index.ts              # Экспорты app layer
```

**Соответствие FSD**: ✅ Полное соответствие
- Содержит только инициализацию и конфигурацию
- Не содержит бизнес-логики
- Зависит только от shared слоя

### 2. **Widgets Layer** (`src/widgets/`)
**Назначение**: Композитные блоки - порталы и дашборды

```

```

**Соответствие FSD**: ✅ Полное соответствие
- Композирует features и entities
- Предоставляет готовые блоки интерфейса
- Изолированная бизнес-логика

**Назначение**: Переиспользуемые ресурсы, инфраструктура

```

│   ├── molecules/       # Молекулярные компоненты
│   ├── organisms/       # Организмы

├── types/               # TypeScript типы
├── utils/               # Утилиты
└── index.ts             # Экспорты shared layer
```

**Соответствие FSD**: ✅ Полное соответствие
- Не зависит от других слоев
- Переиспользуется во всех слоях
- Содержит инфраструктурный код

## Анализ соответствия принципам

### ✅ FSD (Feature-Sliced Design)

1. **Слоистая архитектура**: Четкое разделение на 5 слоев
2. **Изоляция фич**: Каждая фича независима и самодостаточна
3. **Переиспользование**: Entities и Shared переиспользуются в Features
4. **Зависимости**: Соблюдается правило зависимостей (слои зависят только от нижележащих)
5. **Публичные API**: Каждый слой экспортирует только необходимые интерфейсы

### ✅ Atomic Design

1. **Атомы**: Базовые UI компоненты (Button, Input, etc.)
2. **Молекулы**: Простые композиции атомов (SearchInput, CallCard)
3. **Организмы**: Сложные композиции (DepartmentSelector, CallList)
4. **Шаблоны**: Макеты страниц (MainLayout)
5. **Страницы**: Реализуются в widgets layer

### ✅ React Best Practices

1. **Компонентный подход**: Все UI элементы - компоненты
2. **TypeScript**: Полная типизация
3. **Контексты**: Управление состоянием через React Context
4. **Хуки**: Переиспользуемая логика в хуках
5. **Error Boundaries**: Обработка ошибок

## Сильные стороны архитектуры

1. **Масштабируемость**: Легко добавлять новые фичи
2. **Переиспользование**: Компоненты и логика переиспользуются
3. **Изоляция**: Изменения в одной фиче не влияют на другие
4. **Тестируемость**: Каждый слой можно тестировать независимо
5. **Читаемость**: Четкая структура и именование

## Заключение

- Легкое масштабирование
