# 🚀 CI/CD исправление проблемы с модулем zod

## 📋 Обзор

У вас настроен CI/CD pipeline, который автоматически применяет исправления для проблемы с модулем `zod`. Это позволяет быстро развертывать исправления без ручного вмешательства.

## 🔧 Доступные Workflows

### 1. Основной Deploy Workflow
**Файл:** `.github/workflows/deploy.yml`

**Триггеры:**
- Push в ветку `main`
- Ручной запуск (workflow_dispatch)

**Что делает:**
- Устанавливает зависимости в shared библиотеках
- Запускает диагностику модулей
- Собирает приложение
- Проверяет наличие `zod` в собранных файлах
- Развертывает на VPS
- Проверяет работоспособность

### 2. Экстренный Zod Fix Workflow
**Файл:** `.github/workflows/emergency-zod-fix.yml`

**Триггеры:**
- Только ручной запуск (workflow_dispatch)

**Что делает:**
- Комплексная диагностика модулей
- Принудительная пересборка (опционально)
- Детальная проверка `zod` файлов
- Развертывание с дополнительными проверками

## 🚀 Как использовать

### Автоматическое развертывание

1. **Закоммитьте исправления в main:**
   ```bash
   git add .
   git commit -m "fix: исправление проблемы с модулем zod"
   git push origin main
   ```

2. **Следите за выполнением:**
   - Перейдите в GitHub → Actions
   - Найдите workflow "Deploy to VPS"
   - Следите за выполнением

### Ручной запуск экстренного исправления

1. **Перейдите в GitHub Actions:**
   - GitHub → Actions → Emergency Zod Module Fix

2. **Запустите workflow:**
   - Нажмите "Run workflow"
   - Выберите ветку (обычно `main`)
   - Включите "Принудительная пересборка" если нужно
   - Нажмите "Run workflow"

## 📊 Мониторинг выполнения

### Проверка статуса

1. **GitHub Actions:**
   - Зеленая галочка = успешно
   - Красный крестик = ошибка
   - Желтый кружок = выполняется

2. **Логи выполнения:**
   - Нажмите на workflow
   - Нажмите на job
   - Разверните нужный step

### Ключевые проверки

#### ✅ Успешные проверки:

## 🔍 Диагностика проблем

### Если workflow завершился с ошибкой:

1. **Проверьте логи:**
   - Найдите красный step в GitHub Actions
   - Разверните его и прочитайте логи

2. **Частые проблемы:**

   **Проблема:** `zod файлы НЕ найдены`
   **Решение:** Проверьте конфигурацию Vite и зависимости

   **Проблема:** `Backend не работает`
   **Решение:** Проверьте PM2 логи на сервере

   **Проблема:** `Клиент недоступен`
   **Решение:** Проверьте nginx конфигурацию

3. **Ручная диагностика на сервере:**
   ```bash
   # Подключитесь к VPS
   ssh user@your-vps
   
   # Проверьте статус
   cd /var/www/app
   pm2 status
   pm2 logs roleplayidentity
   
   # Проверьте файлы
   find dist -name "*zod*" -type f
   ls -la dist/apps/client/js/
   ```

```bash

# Принудительная пересборка
npm run force-rebuild

# Проверьте сборку
npm run build:production

# Проверьте файлы
find dist -name "*zod*" -type f
```

### Проверка конфигурации:

```bash

grep -n "zod" apps/client/vite.config.ts
```

## 📈 Оптимизация

### Ускорение деплоя:

1. **Кэширование:**
   - GitHub Actions кэширует `node_modules`
   - Используйте `npm ci` вместо `npm install`

2. **Параллельные задачи:**
   - Установка зависимостей и диагностика выполняются параллельно

3. **Условные проверки:**
   - Некоторые проверки выполняются только при необходимости

### Мониторинг производительности:

```bash

time npm run build:production

# Проверьте размер файлов
du -sh dist/apps/client/js/
du -sh dist/apps/mdtclient/js/
```

## 🚨 Экстренные ситуации

### Если сайт не работает:

1. **Быстрое исправление:**
   - Запустите "Emergency Zod Module Fix"
   - Включите "Принудительная пересборка"

2. **Ручное исправление на сервере:**
   ```bash
   ssh user@your-vps
   cd /var/www/app
   
   # Принудительная пересборка
   npm run force-rebuild
   
   # Перезапуск
   pm2 restart roleplayidentity
   ```

3. **Откат к предыдущей версии:**
   ```bash
   # На сервере
   cd /var/www/app
   git log --oneline -5
   git checkout <commit-hash>
   pm2 restart roleplayidentity
   ```

## 📞 Поддержка

### Если CI/CD не работает:

1. **Проверьте секреты:**
   - `VPS_HOST`
   - `VPS_USER`
   - `DEPLOY_KEY`
   - `VITE_SUPABASE_URL`
   - `VITE_SUPABASE_ANON_KEY`

2. **Проверьте права доступа:**
   - SSH ключ должен быть добавлен в GitHub Secrets
   - Пользователь должен иметь права на VPS

3. **Проверьте VPS:**
   - Достаточно места на диске
   - PM2 установлен
   - nginx работает

### Полезные команды:

```bash
# Проверка статуса на VPS
pm2 status
pm2 logs roleplayidentity

# Проверка nginx
sudo nginx -t
sudo systemctl status nginx

# Проверка места на диске
df -h
du -sh /var/www/app/
```
