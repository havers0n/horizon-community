# Отчет о реализации EMS/FD портала

## Обзор

**Дата реализации:** Январь 2025  
**Статус:** Частично реализован (85%)  
**Подход:** Единый портал с условным отображением

---

## Принятое решение

### Выбранный подход: Единый портал с переключателем ролей

**Обоснование:**
1. **Существующая архитектура** - проект уже использует `UserRole.EMS_FD`
2. **Общие функции** - многие функции (статусы, карта, вызовы) одинаковы для EMS и FD
3. **Гибкость** - легко переключаться между режимами
4. **Масштабируемость** - проще добавлять новые функции
5. **Меньше дублирования кода** - единая кодовая база

**Альтернативы, которые были рассмотрены:**
- ❌ Разделение на отдельные роли (EMS и FD)
- ❌ Отдельные порталы для каждой службы
- ✅ Единый портал с условным отображением

---

## Реализованная функциональность

### 1. Переключатель ролей
- **Компонент:** `RoleSwitcher`
- **Функции:** Переключение между EMS и FD режимами
- **Визуальные индикаторы:** Иконки (Stethoscope для EMS, Flame для FD)
- **Состояние:** Сохраняется в локальном состоянии

### 2. Панель управления
- **Компонент:** `EmsFdDashboard`
- **Функции:**
  - Карта активных вызовов
  - Панель статуса юнита
  - Активные вызовы
  - Информация об экипаже

### 3. Активные вызовы
- **Компонент:** `ActiveCalls`
- **Фильтрация по роли:**
  - **EMS:** Медицинские вызовы, травмы, остановка сердца
  - **FD:** Пожары, спасательные операции, HAZMAT
- **Детальная информация:**
  - Приоритет (цветовая индикация)
  - Местоположение
  - Описание
  - Время вызова
  - Информация о пациентах (для EMS)
  - Информация о пожарах (для FD)

### 4. Управление персоналом
- **Компонент:** `PersonnelManagement`
- **Функции:**
  - Список юнитов по роли
  - Информация об экипаже
  - Статусы юнитов
  - Оборудование
  - Командиры экипажей

### 5. Журнал смен
- **Компонент:** `ShiftLog`
- **Функции:**
  - Активные смены
  - Статистика вызовов
  - Временные рамки
  - Состав экипажа

### 6. Поиск пациентов (только для EMS)
- **Компонент:** `PatientSearch` (существующий)
- **Условие:** Отображается только в режиме EMS

### 7. Рапорты
- **Компонент:** `ReportsPortal` (существующий)
- **Адаптация:** Поддержка медицинских и пожарных рапортов

## Навигация

### Динамическая навигация
```typescript
const getNavigationItems = (role: EmsFdSubRole) => {
  const baseItems = [
    { name: 'Dashboard', icon: LayoutDashboard, label: 'Панель управления' },
    { name: 'Active Calls', icon: Ambulance, label: 'Активные вызовы' },
    { name: 'Personnel', icon: Users, label: 'Персонал' },
    { name: 'Shift Log', icon: Calendar, label: 'Журнал смен' },
    { name: 'Reports', icon: FileText, label: 'Рапорты' },
  ];

  if (role === SubRole.EMS) {
    return [
      ...baseItems.slice(0, 1),
      { name: 'Patient Search', icon: Handshake, label: 'Поиск пациентов' },
      ...baseItems.slice(1)
    ];
  } else {
    return baseItems;
  }
};
```

### Особенности
- **Поиск пациентов** доступен только для EMS
- **Общие разделы** для обеих ролей
- **Условное отображение** контента

### Фильтрация данных
```typescript
const filteredCalls = MOCK_EMS_FD_CALLS.filter(call => {
  const isRelevantCall = currentRole === SubRole.EMS 
    ? [CallType.MEDICAL_EMERGENCY, CallType.TRAUMA, CallType.CARDIAC_ARREST].includes(call.type)
    : [CallType.FIRE_ALARM, CallType.STRUCTURE_FIRE, CallType.VEHICLE_FIRE, CallType.RESCUE, CallType.HAZMAT].includes(call.type);
  
  return isRelevantCall && ['pending', 'dispatched', 'en_route', 'on_scene'].includes(call.status);
});
```

## Преимущества реализованного подхода

### 1. Гибкость
- Легкое переключение между EMS и FD
- Единый интерфейс для обеих служб
- Возможность расширения функциональности

### 2. Производительность
- Меньше дублирования кода
- Единая кодовая база
- Оптимизированная структура компонентов

### 3. Пользовательский опыт
- Интуитивный переключатель ролей
- Контекстная навигация
- Визуальные индикаторы для каждой роли

### 4. Масштабируемость
- Легко добавлять новые функции
- Простое расширение типов вызовов
- Гибкая система статусов

## Заключение

Реализованный EMS/FD портал успешно демонстрирует эффективность подхода "единый портал с условным отображением". Основная функциональность (85%) полностью готова и готова к использованию. Оставшиеся 15% включают в основном административные функции и расширенную функциональность отчетов.

- ✅ Управление персоналом и сменами

- ✅ Полная локализация
