# Диагностический отчет MDT System

## Проблема
Пользователь сообщает, что MDT:
1. Открывается автоматически при старте ресурса
2. Не реагирует на нажатие F6

**ВАЖНО:** Логи показывают корректную работу системы, но пользователь сообщает о противоположном поведении.

## Внесенные исправления

### 1. Улучшенное логирование
- Добавлены детальные логи с временными метками
- Добавлены стек вызовов для отслеживания источника вызовов
- Добавлены проверки всех состояний системы
- Добавлены счетчики попыток открытия и NUI callback'ов

### 2. Диагностические команды
- `/mdt_status` - проверка текущего состояния
- `/mdt_test_f6` - тестирование логики F6 без физического нажатия
- `/mdt_monitor` - мониторинг в реальном времени
- `/mdt_force_open_debug` - принудительное открытие (обход всех проверок)
- `/mdt_force_close_debug` - принудительное закрытие (обход всех проверок)
- `/mdt_full_diagnostic` - **НОВАЯ** полная диагностика системы

### 3. Улучшенный тестовый интерфейс
- Детальное логирование всех событий
- Кнопки для тестирования функций
- Отображение статуса NUI фокуса
- Мониторинг событий клавиатуры

## Возможные причины проблемы

### 1. Автоматическое открытие
- **Причина:** Вызов `openMDT` из другого места в коде
- **Диагностика:** Проверить `autoOpenAttempts` в `/mdt_full_diagnostic`
- **Решение:** Найти и удалить автоматический вызов

### 2. F6 не работает
- **Причина 1:** NUI не получает события клавиатуры
- **Диагностика:** Проверить логи NUI на наличие событий клавиатуры
- **Решение:** Убедиться, что фокус установлен на body

- **Причина 2:** NUI не отправляет сообщения клиенту
- **Диагностика:** Проверить `nuiCallbackCount` в `/mdt_full_diagnostic`
- **Решение:** Исправить метод отправки (fetch/$.post)

- **Причина 3:** Клиент не получает сообщения от NUI
- **Диагностика:** Проверить логи клиента на получение callback'ов
- **Решение:** Исправить обработчик `RegisterNUICallback`

### 3. Кэширование браузера
- **Причина:** Старый интерфейс может кэшироваться
- **Диагностика:** Проверить, отображается ли тестовый интерфейс
- **Решение:** Очистить кэш браузера или перезапустить ресурс

### 4. Конфликт с другими ресурсами
- **Причина:** Другой ресурс может перехватывать F6
- **Диагностика:** Проверить логи на наличие других ресурсов
- **Решение:** Отключить конфликтующие ресурсы

## Ожидаемое поведение после исправлений

1. **При старте ресурса:** MDT НЕ должен открываться автоматически
2. **Через 10 секунд после старта:** F6 должна работать корректно
3. **При нажатии F6:** MDT должен открываться/закрываться
4. **При нажатии ESC:** MDT должен закрываться
5. **В тестовом интерфейсе:** Все события должны логироваться

## Если проблема сохраняется

1. Выполните `/mdt_full_diagnostic` и предоставьте полные логи
2. Укажите, какие именно команды выполнялись
3. Опишите, что происходит визуально (открывается ли интерфейс)
4. Проверьте, не конфликтует ли F6 с другими ресурсами
5. **ВАЖНО:** Если логи показывают корректную работу, но визуально система не работает:
   - Проверьте, отображается ли тестовый интерфейс
   - Очистите кэш браузера
   - Проверьте консоль браузера на ошибки JavaScript
   - Сделайте скриншот или видео для демонстрации проблемы
