# ОТЧЕТ О ПРОБЛЕМЕ: TestService и схема MDT

## 🎯 ДИАГНОЗ ПРОБЛЕМЫ

**Проблема:** Ошибка PGRST106 при создании тестов через TestService
```
Error: The schema must be one of the following: public, graphql_public
```

## 🔍 РЕЗУЛЬТАТЫ ДИАГНОСТИКИ

### ✅ Что работает правильно:
1. **TestService инициализируется корректно** - получает клиент с правильной схемой MDT
2. **Клиенты Supabase создаются правильно** - `mdtSupabase.__SCHEMA: MDT`
3. **Код TestService написан корректно** - использует правильные типы и методы
4. **Тесты проходят успешно** - логика сервиса работает в изоляции

### ❌ Что не работает:
1. **Конфигурация клиента** - `schema: undefined` в отладочной информации
2. **Supabase сервер** - не знает о схеме `mdt` в PostgREST конфигурации
3. **Все запросы к схеме mdt** - падают с ошибкой PGRST106

## 🛠️ ПРОБЛЕМЫ В КОНФИГУРАЦИИ SUPABASE

### Проблема 1: PostgREST не знает о схеме `mdt`
```
Error: The schema must be one of the following: public, graphql_public
```

**Решение:** Нужно добавить схему `mdt` в конфигурацию PostgREST в Supabase.

### Проблема 2: Клиент Supabase не передает схему
```
[DEBUG] this.db configuration: {
  schema: undefined,  // <-- Проблема здесь
  headers: { 'X-Client-Info': 'supabase-js-node/2.53.0', 'X-Schema': 'mdt' }
}
```

**Решение:** Конфигурация схемы не применяется к клиенту.

## 📋 ПЛАН ИСПРАВЛЕНИЯ

### Шаг 1: Настройка PostgREST в Supabase
1. Открыть Supabase Dashboard
2. Перейти в Settings > Database
3. Найти конфигурацию PostgREST
4. Добавить схему `mdt` в список разрешенных схем

### Шаг 2: Проверка RLS политик
1. Убедиться, что RLS политики настроены для схемы `mdt`
2. Проверить права доступа service_role ключа

### Шаг 3: Альтернативное решение
Если настройка PostgREST невозможна, можно:
1. Создать таблицы в схеме `public`
2. Использовать префиксы для разделения данных
3. Настроить представления (views) для изоляции данных

## 🔧 ВРЕМЕННОЕ РЕШЕНИЕ

До исправления конфигурации Supabase можно:

1. **Использовать схему `public`** с префиксами таблиц:
   ```sql
   CREATE TABLE public.mdt_tests (...)
   CREATE TABLE public.mdt_test_results (...)
   ```

2. **Обновить TestService** для работы с таблицами в схеме `public`:
   ```typescript
   // Вместо mdtSupabase использовать обычный supabase
   private db = supabase;
   
   // В запросах использовать префикс
   .from("mdt_tests")
   ```

## 🎯 ВЫВОД

Проблема **НЕ в коде TestService**, а в **конфигурации Supabase сервера**. 
Схема `mdt` не зарегистрирована в PostgREST, поэтому все запросы к ней отклоняются.

**Требуется вмешательство администратора Supabase** для настройки PostgREST конфигурации.
