Техническое задание на разработку системы CAD/MDT для игрового проекта
Версия: 1.0
Дата: 25.05.2024
1. Общее описание и цели проекта
Цель: Разработать комплексную веб-систему CAD/MDT (Computer-Aided Dispatch / Mobile Data Terminal) для управления данными и процессами в рамках игрового RP-проекта. Система должна обеспечивать взаимодействие между различными департаментами (гражданские, полиция, пожарные/медики, диспетчеры), предоставляя каждому из них специализированный функционал.
Ключевые сущности: Персонаж (гражданский), Офицер, Сотрудник EMS/FD, Диспетчер, Транспортное средство (Т/С), Оружие, Вызов 911, Отчет, Ордер, BOLO.
2. Глобальные модули и системы
2.1. Авторизация и управление доступом
2.1.1. Синхронизация с Личным кабинетом (ЛК): Авторизация в CAD/MDT происходит автоматически при переходе по ссылке, если пользователь авторизован в основном ЛК проекта в том же браузере.
2.1.2. Ролевая модель: Доступ к вкладкам и функционалу департаментов определяется ролями пользователя в ЛК (e.g., Civil Department, Police Department, Fire Department, Dispatch Department). Пользователь видит только те вкладки, к которым у него есть доступ.
2.2. Игровые интеграции (FiveM)
2.2.1. Планшет: Вся система CAD/MDT должна быть доступна в игре через интерфейс планшета, открывающегося по заданной кнопке.
2.2.2. Команды чата:
/sn-auth [token]: Авторизация в игре. Токен генерируется в настройках профиля CAD.
/isactive: Отображает ID и имя активного персонажа/юнита.
/set [статус]: Изменение статуса юнита (e.g., /set Доступен).
/tstop [описание]: Создание инцидента "траффик-стоп" с автоматическим определением местоположения и прикреплением юнита.
/panic: Активация кнопки паники.
/911 [текст]: Создание текстового вызова 911 с автоматическим определением местоположения.
2.2.3. HUD интеграция:
Отображение текущей "игровой зоны", установленной диспетчером.
Отображение текущей загруженности юнитов (НИЗКАЯ, СРЕДНЯЯ, ВЫСОКАЯ) цветом.
Отображение глобального сигнала "100" при его активации.
2.2.4. ALPR (Automatic License Plate Reader):
Интеграция с базой данных Т/С.
Привязка к кнопкам (Numpad 9 - передний радар, Numpad 6 - задний).
Возможность проверки номерных знаков и добавления их в BOLO напрямую из интерфейса радара.

Техническое Задание: Модуль «Гражданин» (Citizen)
1. Общее описание
Модуль «Гражданин» представляет собой комплексный интерфейс для создания, управления и взаимодействия с данными граждан, их имуществом, документами и активностями в рамках системы. Все описанные функции должны быть реализованы в едином разделе «Citizen».
2. Основные функциональные блоки
Главное меню раздела «Гражданин» должно предоставлять доступ к следующим основным действиям:
Создание нового гражданского профиля.
Создание вызова службы 911.
Регистрация оружия.
Регистрация транспортного средства.
Просмотр и управление существующими гражданскими профилями.
3. Создание и управление гражданским профилем
Процесс создания нового гражданина представляет собой многостраничный мастер (wizard).
3.1. Страница 1: Основная информация
Форма для ввода базовых данных о гражданине.
Поля для заполнения:
Имя: Текстовое поле. Обязательно.
Фамилия: Текстовое поле. Обязательно.
Дата рождения: Поле для ввода даты (формат ДД.ММ.ГГГГ) с виджетом календаря. Обязательно.
Номер социального страхования: Поле. Генерируется автоматически при создании. Формат: ###-##-####. Недоступно для редактирования. (Опционально)
Пол: Выпадающий список (Select). Обязательно.
Этническая принадлежность: Выпадающий список (Select). Обязательно.
Цвет волос: Текстовое поле. Обязательно.
Цвет глаз: Текстовое поле. Обязательно.
Вес (kg): Числовое поле. Обязательно.
Рост (cm): Числовое поле. Обязательно.
Почтовый код: Выпадающий список или текстовое поле с автозаполнением. (Опционально)
Адрес: Текстовое поле. Функциональное требование: Адрес должен автоматически подставляться на основе выбранного почтового кода.
Кнопки навигации:
Отменить (Cancel)
Next → (Далее)
Дополнительная функция:
Реализовать кнопку или опцию «Сгенерировать случайные данные», которая будет автоматически заполнять все поля на этой странице (кроме лицензий) валидными случайными значениями.
3.2. Страница 2: Дополнительная информация
Поля для заполнения:
Номер телефона: Текстовое поле. (Опционально)
Род занятий: Текстовое поле. (Опционально)
Дополнительная информация: Большое текстовое поле (Textarea). (Опционально)
3.3. Страница 3: Лицензии
Список для выбора имеющихся у гражданина лицензий. Все поля — выпадающие списки (Select) и являются опциональными.
Водительская лицензия
Категории водительской лицензии
Легкая лицензия (вероятно, на легкомоторный транспорт)
Категории летной лицензии
Лицензия на водный транспорт
Категории лицензий на водный транспорт
Лицензия на рыбалку
Категории лицензий на рыбалку
Лицензия на охоту
Категории лицензий на охоту
Лицензия на оружие
Категории лицензий на оружие
Другие категории лицензий
3.4. Страница 4: Медицинская карта
Раздел для внесения медицинских данных гражданина.
Список болезней: Выпадающий список.
Список хронических заболеваний: Выпадающий список.
Аллергии: Текстовое поле.
Группа крови: Выпадающий список.
Резус-фактор: Выпадающий список.
Перенесенные операции: Текстовое поле.
Наличие имплантатов: Текстовое поле.
3.5. Страница 5: Судебные и правовые записи
Раздел для регистрации правонарушений, связанных с гражданином. Доступен при просмотре уже созданного профиля.
Интерфейс:
Отображение списка существующих записей (штрафы, аресты, предупреждения).
При отсутствии записей выводится сообщение "No records selected yet".
Кнопки действий:
Создать штраф
Создать письменное предупреждение
Создать отчёт об аресте
3.6. Страница 6: Создание профиля офицера
Эта страница/функция доступна только для пользователей с определенной ролью (например, "PD" - Police Department).
Поля для заполнения:
Номер жетона: Поле. Функциональное требование: Должна быть возможность генерации случайного 5-значного номера.
Позывной Символ 1: Текстовое поле.
Позывной Символ 2: Текстовое поле.
Департамент: Выпадающий список.
Подразделение: Выпадающий список.
4. Регистрация имущества
4.1. Регистрация транспортного средства (Т/С)
Интерфейс: Модальное окно или отдельная страница.
Поля для заполнения:
Номерной знак: Текстовое поле.
Модель: Выпадающий список.
Владелец: Выпадающий список (выбор из существующих граждан).
Цвет: Текстовое поле.

VIN: Текстовое поле. Функциональное требование: Реализовать кнопку для генерации случайного VIN-номера. (Опционально)
Статус регистрации: Выпадающий список.
Статус страховки: Выпадающий список.
Статус инспекции: Выпадающий список. (Опционально)
Статус налогов: Выпадающий список. (Опционально)
4.2. Регистрация оружия
Интерфейс: Модальное окно.
Поля для заполнения:
Модель: Текстовое поле.
Владелец: Выпадающий список (выбор из существующих граждан).
Статус регистрации: Выпадающий список.
Серийный номер: Текстовое поле. Функциональное требование: Реализовать кнопку для генерации случайного серийного номера. (Опционально)
Кнопки: Cancel, Зарегистрировать оружие.
5. Система вызовов 911
5.1. Создание вызова 911 (со стороны диспетчера)
Интерфейс: Простая форма.
Поля:
Адрес: Текстовое поле.
Информация по вызову: Большое текстовое поле (Textarea).
5.2. Голосовой вызов 911 (со стороны гражданина/игрока)
Механика:
При нажатии на кнопку вызова 911 на экране появляется всплывающее уведомление (плашка) с текстом: «Ваш звонок отправлен, ожидайте ответа оператора.»
Сценарий 1 (успешный): Оператор принимает звонок. Текст в уведомлении меняется на: «Ваш звонок принят, перейдите в канал для разговора с оператором». После этого пользователь может самостоятельно закрыть уведомление.
Сценарий 2 (неуспешный): Оператор отклоняет звонок. Появляется уведомление с текстом: «Ваш звонок отклонен». Уведомление закрывается автоматически через несколько секунд.

Поля: Гражданин (работник), Компания (выпадающий список).

Техническое Задание: Модуль «LAW» (Правоохранительная панель)
1. Общее описание
Модуль «LAW» — это комплексный интерфейс для сотрудников правоохранительных органов (LEO), предназначенный для поиска информации, управления юнитами, составления отчетов и взаимодействия с другими службами.
2. Главная панель управления (Dashboard)
Основной экран модуля, предоставляющий быстрый доступ ко всем ключевым функциям.
Компоновка: Все кнопки действий должны быть расположены в один или несколько рядов для удобного доступа.
Кнопки действий:
Поиск по имени
Поиск по номерному знаку
Поиск оружия
Поиск бизнеса (функционал не описан, предполагается поиск по названию компании)
Поиск по пользовательскому полю (функционал не описан, требует уточнения)
Вызвать 911
Создать письменное предупреждение
Создать штраф
Создать отчёт об аресте
Создать ордер
Создать BOLO (Be On Look Out - ориентировка)
Блокнот (для личных записей офицера)
3. Функции поиска
3.1. Поиск человека по имени
Интерфейс: Одно поле для ввода «Полное имя».
Механика:
При вводе первых букв имени/фамилии или цифр номера соц. страхования (SSN) система должна отображать выпадающий список с подсказками (live search).
После выбора человека из списка или успешного поиска открывается его детальная карточка.
3.2. Поиск автомобиля
Интерфейс: 4 поля для ввода: Номерной знак, Модель, Цвет, Тип автомобиля.
Механика:
Любое из полей может быть оставлено пустым. Поиск выполняется по заполненным критериям.
В результатах поиска отображается список подходящих автомобилей.
Интерактивность: Имя владельца (ФИО) в результатах должно быть кликабельным и вести на карточку соответствующего гражданина.
3.3. Поиск оружия
Интерфейс: 2 поля для ввода: Серийный номер / Модель, Владелец.
Механика:
В результатах поиска отображается информация об оружии.
Интерактивность: Имя владельца (ФИО) в результатах должно быть кликабельным и вести на карточку гражданина.
3.4. Поиск по адресу
Интерфейс: Одно поле для ввода адреса или почтового кода.
Механика: Возвращает список граждан, зарегистрированных по данному адресу.
4. Карточка гражданина (Профиль)
Детализированное представление информации о гражданине, открывающееся после поиска.
Структура:
Основная информация: Полное имя, SSN, дата рождения, пол, вес, рост, контакты и т.д.
Лицензии: Список имеющихся лицензий.
Баллы лицензий: Отображение штрафных баллов по каждой категории лицензий.
Вкладки (Tabs):
Зарегистрированный транспорт: Список Т/С.
Зарегистрированное оружие: Список оружия.
Штрафы: Список выписанных штрафов.
Аресты: Список арестов с деталями (номер дела, офицер, статус).
Письменные предупреждения.
Ордера.
Питомцы: Новый раздел.
Интерактивность:
Все элементы в списках транспорта и оружия должны быть кликабельными, открывая соответствующую карточку (Т/С или оружия).
Кнопки Редактировать, Удалить, Экспорт для записей об арестах.
Кнопки Редактировать баллы лицензий, Управлять флагами граждан.
Раздел «Питомцы»:
Отображает информацию о питомцах гражданина: кличка, порода, цвет, вес.
Должна быть возможность просмотра медицинских записей и заметок о питомце.
5. Управление отчетами и инцидентами
5.1. Создание отчета об аресте / штрафе
Интерфейс: Многовкладочное модальное окно.
Вкладки:
Общая информация: Гражданин, Адрес инцидента, Время, Тип инцидента, Статья, Краткое описание.
Нарушения: Выбор конкретных статей нарушения из списка.
Изъятые предметы: Возможность добавлять изъятые предметы (Элемент, Количество, флаг Нелегальное).
Информация о транспорте: Данные о Т/С подозреваемого.
Чекбоксы: Эвакуирован, Угнанное транспортное средство.
Дополнительные поля: Изъятые вещи, Оружие подозреваемого (можно оставить пустыми).
6. Управление офицерами и юнитами
6.1. Вкладка «Офицеры»
Функционал:
Список всех созданных офицеров с возможностью редактирования.
Кнопка для регистрации нового офицера (при наличии свободных гражданских профилей).
Редактирование офицера:
Поля: Номер жетона, Позывной, Департамент, Подразделение, Звание, Квалификации, Награды.
6.2. Журнал смен
Функционал: Список офицеров, выходивших на смену, с указанием Даты выхода, Даты окончания и Общего времени на смене.
6.3. Мои отчеты
Функционал: Персональный архив всех отчетов (аресты, штрафы, предупреждения), созданных текущим пользователем. Возможность просмотра и редактирования.
6.4. Управление юнитами (для Администрации и Супервайзеров)
Функционал: Список всех юнитов с возможностью изменять Звание, Квалификации, Подразделение и Департамент.
7. Управление статусами и заступление на смену
7.1. Панель статусов (10-коды)
Интерфейс: Ряд кнопок для быстрой смены статуса.
Статусы:
Доступен (10-8)
Недоступен (10-7)
Временно недоступен (10-6)
В пути (10-31)
На инциденте (10-97)
Занят (10-12)
7.2. Механика заступления на смену
При нажатии на кнопку Доступен (10-8) открывается модальное окно «Выберите офицера».
Поля в окне:
Офицер (выпадающий список)
Патрульный автомобиль (опционально)
Пользовательские позывные (опционально)
Ролевая логика:
Супервайзер: Появляется ползунок Выйти на смену как супервайзер.
Специальные квалификации: Если у офицера есть квалификации (TU, ASD, K-9 и т.д.), появляется кнопка Заступить как [Название квалификации].
Автоматические позывные:
Система должна автоматически присваивать позывные в зависимости от типа патруля (юнита):
TU -> 1T-xx
MBU -> 1M-xx
K-9 -> K-9-xx
CVE -> 1C-xx
AIR -> AIR-1/2/3
xx - номер позывного юнита. Поле «Пользовательские позывные» при этом не используется.
7.3. Парные юниты
Интерфейс: В окне заступления на смену добавить ползунок Парный юнит.
Механика:
При активации ползунка открывается окно с полями:
Ваш позывной (определяется автоматически)
Позывной напарника (ввод и выбор из списка офицеров)
Кастомный позывной (для парного юнита)
Объединяться можно с юнитами, которые еще не на смене.
При добавлении в патруль оба офицера автоматически получают статус Доступен.
Объединение в парные юниты доступно при наличии квалификаций или если второй офицер заступил как супервайзер.
8. Система оповещений (Сигналы)
8.1. Сигналы для игроков (от Супервайзера)
Доступ: Только для роли «супервайзер».
Механика:
Кнопка Сигналы открывает меню.
При заполнении и отправке у всех игроков в сессии появляется всплывающее уведомление (плашка) с текстом сигнала.
8.2. Кнопка паники
Механика: При активации воспроизводится кастомный звуковой сигнал и всем LEO отправляется уведомление (плашка) об активации.
8.3. Отправка сигналов LEO / EMS / FD
Интерфейс: Модальное окно с переключателями Сигнал EMS/FD и Сигнал LEO.
Поля: Описание (текстовое поле).
Функционал: Отправляет целевое уведомление выбранным департаментам.
9. Информационные модули
Статьи: Справочник статей уголовного/административного/дорожного кодексов с поиском по названию.
Штрафстоянки: Список эвакуированных Т/С с подробной информацией.
История вызовов: Лог всех вызовов 911 с подробной информацией.
Журнал граждан: Общий журнал всех граждан, в отношении которых производились правовые действия (штрафы, аресты, предупреждения), с поиском по имени.


5. Модуль "Пожарный Департамент и EMS" (FD/EMS)
5.1. Структура вкладок
Панель управления
Сотрудники
Журнал смен
История вызовов
5.2. Вкладка "Панель управления"
5.2.1. Создать отчет EMS: Форма с полями: ФИО, диагноз (МКБ), группа крови, хрон. заболевания (МКБ), кол-во пострадавших, тип инцидента, статус пострадавших (госпитализация/нет/мертв), адрес, дата/время, ФИО ст. парамедика, доп. информация. Возможность добавлять страницы в отчет.
5.2.2. Создать отчет FD: Форма с полями: Тип инцидента, кол-во пострадавших, описание, дата/время, место, ФИО супервайзера.
5.2.3. Поиск по имени: Выводит медкарту персонажа (ФИО, группа крови, заболевания, история вызовов EMS).
5.2.4. Поиск болезни: Поиск по базе МКБ, выводит краткую информацию и методы лечения.
5.3. Прочие вкладки
Сотрудники: Список сотрудников, зарегистрированных с аккаунта пользователя.
Журнал смен: Аналогично п. 4.4.
История вызовов: Архив вызовов с отчетами о работе на них.
6. Модуль "Диспетчерский Департамент" (Dispatch)
6.1. Структура вкладок
Панель управления
Карта
6.2. Вкладка "Панель управления"
6.2.1. Функции поиска: Аналогично п. 4.2.1 (человек, Т/С, оружие).
6.2.2. Инструменты:
Блокнот для записей.
Создать BOLO: Форма с полями: ФИО/описание, транспорт, подробное описание.
Создать ордер: Форма с полями: ФИО, тип ордера, адрес (для обыска), причина, автор запроса.
Изменить игровую зону: Текстовое поле для ввода названия зоны (интегрируется с HUD).
Активировать сигнал 100: Воспроизводит звук и выводит оповещение.
6.2.3. Управление статусом:
Кнопки статусов: Оператор, Трафик-диспетчер, Активный контроль, Недоступен.
Индикация: Статус диспетчеров (присутствует/отсутствует) отображается в панели управления гражданского департамента с цветовой индикацией (зеленый/красный).
Звуковой сигнал: При заступлении диспетчера на смену в статусе "Оператор" у гражданских воспроизводится звуковой сигнал.
6.2.4. Обработка голосового вызова 911:
У диспетчера в статусе "Доступен" появляется модальное окно "Поступил звонок в 911" с кнопками "Принять" и "Отклонить".
Логика ответа/отклонения описана в п. 3.2.3.
6.3. Вкладка "Карта"
6.3.1. Основа: Интерактивная Live-карта (с возможностью замены файлов карты).
6.3.2. Отображение юнитов: На карте в реальном времени отображаются метки всех активных юнитов (PD, FD, EMS, CD).
6.3.3. Интерактивность юнитов:
При клике на юнит открывается боковая панель с информацией: ФИО, позывной, статус, адрес (real-time), департамент, подразделение.
Возможность слежения камерой за юнитом.
Возможность прикрепить/открепить юнит к вызову, изменить его статус.
При включении сирен у юнита в игре, его метка на карте должна анимироваться (мигать).
6.3.4. Управление вызовами:
Вызовы отображаются в списке в углу карты.
На карте вызовы отображаются в виде "блипов".
Блип можно перемещать. При клике на него открывается подробная информация и меню управления вызовом (назначение юнитов, изменение статуса и т.д.).
7. Общая информационная панель (Dashboard)
7.1. Назначение
Общая сводная панель, видимая всем департаментам (PD/FD/EMS/DD), для быстрой оценки обстановки.
7.2. Структура блоков
7.2.1. Список активных юнитов (вместо "активные офицеры"):
Супервайзеры: Отдельный блок для всех супервайзеров на смене, независимо от департамента.
Юниты по подразделениям: Блоки для каждого подразделения (e.g., LAPD Patrol Division, LASD SEB, LAPD Detective Bureau, LACoFD и т.д.).
Юниты по квалификациям: Отдельный блок, куда попадают юниты, вышедшие на смену с особой квалификацией (TU, ASD, K-9 и т.д.).
7.2.2. Активные вызовы 911: Список текущих вызовов.
7.2.3. Список BOLO: Список активных ориентировок (ФИО/описание, транспорт, причина).
7.3. Кастомизация
Наличие кнопки, позволяющей пользователю изменять порядок отображения блоков на панели (drag-and-drop).
