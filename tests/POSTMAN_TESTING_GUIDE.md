## 🚀 Установка и настройка

### 1. Установка Postman
- Скачайте Postman с официального сайта: https://www.postman.com/downloads/
- Установите приложение
- Создайте аккаунт (опционально, но рекомендуется для синхронизации)

### 2. Подготовка сервера
Убедитесь, что ваш сервер запущен и доступен:
```bash
# Запуск сервера (если используете Next.js)
cd tests
npm run dev

# Или если используете другой сервер
npm start
```

## 📥 Импорт коллекции

### 1. Импорт коллекции API
1. Откройте Postman
2. Нажмите **Import** в левом верхнем углу
3. Выберите файл `postman-collection.json`
4. Нажмите **Import**

### 2. Импорт переменных окружения
1. В Postman перейдите в **Environments** (вкладка слева)
2. Нажмите **Import**
3. Выберите файл `postman-environment.json`
4. Нажмите **Import**
5. Выберите созданное окружение в выпадающем списке

## ⚙️ Настройка переменных окружения

### Основные переменные:
- `base_url` - базовый URL вашего API (по умолчанию: http://localhost:3000)
- `user_token` - токен обычного пользователя
- `admin_token` - токен администратора
- `test_id` - ID теста для тестирования
- `result_id` - ID результата теста

### Настройка токенов:
1. Откройте **Environments** в Postman
2. Выберите ваше окружение
3. Обновите значения токенов:
   ```
   user_token: ваш_токен_пользователя
   admin_token: ваш_токен_администратора
   ```

## 🧪 Тестирование публичных API

### 1. GET /api/tests - Доступные тесты
**Цель**: Получить список доступных тестов

**Шаги**:
1. Откройте запрос "GET /api/tests - Доступные тесты"
2. Убедитесь, что установлен правильный токен в заголовке Authorization
3. Нажмите **Send**

**Ожидаемый результат**:
```json
[
  {
    "id": 1,
    "name": "Тест по API",
    "description": "Описание теста",
    "time": 1800,
    "status": 1
  }
]
```

**Проверки**:
- ✅ Статус код: 200
- ✅ Время ответа < 5 секунд
- ✅ Ответ содержит массив тестов
- ✅ Каждый тест имеет обязательные поля (id, name, status)

### 2. GET /api/tests/:id - Детали теста
**Цель**: Получить детальную информацию о конкретном тесте

**Шаги**:
1. Откройте запрос "GET /api/tests/:id - Детали теста"
2. Убедитесь, что переменная `test_id` установлена
3. Нажмите **Send**

**Ожидаемый результат**:
```json
{
  "id": 1,
  "name": "Тест по API",
  "description": "Описание теста",
  "time": 1800,
  "questions": [
    {
      "id": 1,
      "question": "Вопрос 1?",
      "type": 0,
      "options": ["A", "B", "C", "D"]
    }
  ]
}
```

### 3. POST /api/tests/:id/passing/start - Начало теста
**Цель**: Начать прохождение теста

**Шаги**:
1. Откройте запрос "POST /api/tests/:id/passing/start"
2. Убедитесь, что `test_id` установлен
3. Нажмите **Send**

**Ожидаемый результат**:
```json
{
  "id": 123,
  "testId": 1,
  "status": 1,
  "start": 1640995200,
  "end": 1640997000
}
```

**Важно**: Сохраните `id` из ответа как `result_id` для последующих запросов.

### 4. POST /api/tests/:id/passing/end - Отправка ответов
**Цель**: Отправить ответы и завершить тест

**Шаги**:
1. Откройте запрос "POST /api/tests/:id/passing/end"
2. Обновите тело запроса с правильными ответами:
```json
{
  "result": 123,
  "answers": [
    {
      "questionId": 1,
      "answer": "A"
    },
    {
      "questionId": 2,
      "answer": ["B", "C"]
    }
  ]
}
```
3. Нажмите **Send**

**Ожидаемый результат**:
```json
{
  "id": 123,
  "status": 2,
  "answers": [
    {
      "id": 1,
      "answer": "A",
      "correct": 1
    }
  ]
}
```

### 5. GET /api/result - Результаты теста
**Цель**: Получить результаты завершенного теста

**Шаги**:
1. Откройте запрос "GET /api/result"
2. Убедитесь, что `result_id` установлен
3. Нажмите **Send**

## 🔒 Тесты безопасности

### 1. Проверка авторизации
**Цель**: Убедиться, что API защищен от неавторизованного доступа

**Тесты**:
- GET /api/tests без токена → должен вернуть 403
- POST /api/tests/new с обычным токеном → должен вернуть 403
- POST /api/tests/:id/passing/end с неверными данными → должен вернуть 400/422

### 2. Валидация данных
**Цель**: Проверить корректность валидации входных данных

**Тесты**:
- Отправка неверного формата данных
- Отправка пустых обязательных полей
- Отправка неверных типов данных

## 🤖 Автоматизация тестирования

### 1. Запуск всех тестов
1. В Postman выберите коллекцию
2. Нажмите **Run collection**
3. Выберите окружение
4. Нажмите **Run**

### 2. Настройка CI/CD
Создайте файл `newman-runner.js`:
```javascript
const newman = require('newman');

newman.run({
    collection: require('./postman-collection.json'),
    environment: require('./postman-environment.json'),
    reporters: ['cli', 'json'],
    reporter: {
        json: {
            export: './test-results/api-test-results.json'
        }
    }
}, function (err) {
    if (err) { throw err; }
    console.log('Тесты завершены!');
});
```

### 3. Установка Newman
```bash
npm install -g newman
```

### 4. Запуск через командную строку
```bash
newman run tests/postman-collection.json -e tests/postman-environment.json
```

## 🐛 Устранение неполадок

### Частые проблемы:

#### 1. Ошибка 403 Unauthorized
**Причина**: Неверный или отсутствующий токен
**Решение**:
- Проверьте правильность токена в переменных окружения
- Убедитесь, что токен не истек
- Проверьте формат заголовка Authorization: `Bearer your_token`

#### 2. Ошибка 404 Not Found
**Причина**: Неверный URL или ID ресурса
**Решение**:
- Проверьте правильность `base_url`
- Убедитесь, что `test_id` и `result_id` существуют
- Проверьте правильность пути API

#### 3. Ошибка 500 Internal Server Error
**Причина**: Ошибка на сервере
**Решение**:
- Проверьте логи сервера
- Убедитесь, что база данных доступна
- Проверьте правильность данных в запросе

#### 4. Медленные ответы
**Причина**: Проблемы с производительностью
**Решение**:
- Проверьте нагрузку на сервер
- Убедитесь, что база данных оптимизирована
- Проверьте сетевые настройки

### Отладка в Postman:

#### 1. Просмотр логов
- Откройте **Console** в Postman (View → Show Postman Console)
- Все запросы и ответы будут отображаться в консоли

#### 2. Проверка переменных
- В **Environments** проверьте текущие значения переменных
- Используйте `{{variable_name}}` для отладки

#### 3. Тестирование отдельных запросов
- Запускайте запросы по одному для изоляции проблем
- Проверяйте каждый шаг перед переходом к следующему
